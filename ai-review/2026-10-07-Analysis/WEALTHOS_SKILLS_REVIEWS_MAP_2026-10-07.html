⚡ Performance Bottlenecks: 7 Critical Issues
B1: Single SQLite Connection Serializes All Ops

Root: Callback `sqlite3` driver, one connection in database.ts

Impact: Any import/FIFO write → dashboard reads queue behind it → user clicks stall

Fix: Give reads own read-only connections (3-pool) OR switch to better-sqlite3 (already a dependency)

B2: Cache Invalidation Too Coarse

Root: `registerFifoCompletedCallback` clears *all* dashboard keys + disk cache on any import

Impact: Every import = next load is cold compute (B3)

Fix: Invalidate only affected portfolios; serve stale-while-recompute

B3: buildDashboardPayload: 25 Serial Awaits on Cold Path

Root: 959-line function, full-table reads (no WHERE), unindexed sorts, GROUP BY without filter

Impact: Latency = Σ(query times); 10+ seconds on first load

Fix: Parallelize with `Promise.all`, add WHERE portfolio IN (...), precompute realized totals

B4: 159 Overlapping/Duplicate Indexes on 3.4 GB DB

Root: 14 exact-duplicate indexes; 22 left-prefix redundant; 4 identical (symbol, date) on HistoricalPrices (5M rows)

Impact: Cache pressure, query planner fails heuristics, writes amplified

Fix: Remove redundant indexes; run ANALYZE & PRAGMA optimize; set mmap_size at runtime

B5: Per-Row Awaited Writes with No Transaction

Root: 34 loop sites do `for (…) await dbRun(…)` each in own WAL commit + backup

Impact: Each insert = fsync; backup competes with reads

Fix: Wrap in `BEGIN … COMMIT` with prepared statement

B7: Full 3.4 GB DB Copy After Every Write

Root: `createPersistentBackup()` in `dbRun` callback; fs.promises.copyFile every 10 min if writes occur

Impact: Evicts OS page cache; competes with dashboard reads; copy ignores WAL = not consistent

Fix: Remove per-write trigger; schedule 6-hourly consistent snapshot via VACUUM INTO or db.backup()

B6–B7: N+1 Reads & Unfiltered Selects

Root: SELECT realized_pnl aggregates whole table; symbols pulled from all transactions; OR conditions defeat indexes

Impact: Cold cache → I/O bound; full-table scans

Fix: Add WHERE portfolio IN (...); aggregate in SQL; replace OR with UNION or two queries
