# WealthOS Fundamental Research Program — Independent Audit and Rebuild Specification (V2, 2026-10-10)

**Purpose:** one document that (1) records what an independent audit found when the existing derivation of the per-scrip report was *not* assumed correct, and (2) specifies a rebuilt, repeatable, LLM-agnostic program that produces investor-grade 29-question reports.
**Supersedes:** `WEALTHOS_29Q_SIX_SCRIP_PROGRAM_SPEC_2026-10-10.md` (v1), **except its §4 sub-question table, which stays authoritative** (with the question-number note in §9 below).
**Status:** audit complete; **nothing has been built or changed** in the application, repository code or databases. All database access was read-only.

---

## 0. Headline

**Do not rely on any existing fundamental output** (filter results, 29-question reports, nine-stock decision reports, QGLP scores, AKIKO/YUKEN reports) until they are regenerated by the rebuilt pipeline. The audit found errors at every layer, not only in the final prose:

| Layer | Finding (confirmed by recomputation from real data) |
|---|---|
| Raw → canonical facts | "Quarterly" values are often **year-to-date or full-year** totals (47% of sales/PAT groups conflict; 27,458 promote the cumulative value). Four promoted FY25 quarters sum to 1.69–1.81× the annual for all six scrips. |
| Provider data | A **simulator** writes identical fake values (revenue 950, PAT 85, market cap 4500, promoter 62.5, order book 1850…) under provider `TRENDLYNE_MCP_MAX` for ~967 symbols; they feed reports. |
| Filters | None of the six scrips passes all seven filters; stored results are wrong or missing for most (§3). |
| 29-question pipeline | Almost none of the 29 calculations exists in code; question "readiness" means "a row exists". |
| Reports | Decision labels hard-coded per ticker; some statuses generated from a hash; reports are boilerplate and stale. |
| Trendlyne | 89% of parameter snapshots failed on a quota error; only 277 tokens were ever discovered; 51 mapped. |

**Good news (verified):** many *numbers quoted* in the YUKEN business report match filings (revenue, materials cost, CFO, capex, finance cost); SMA calculations are correct; several independent reconciliations agree (YUKEN FY25 Q4 = 457.356 − 332.705 = 124.651; TATATECH EBITDA 852.95 reproduced exactly). The problem is mostly *what is missing, stale, mislabelled or invented*, and *how verdicts are derived*.

## 4. Rebuilt architecture (LLM-agnostic, repeatable)

```
Identity ▶ Data foundation (clean, point-in-time facts) ▶ Calculators (deterministic) ▶ Gap list
 ▶ Acquisition (Trendlyne gap-first, XBRL/FERE, filings) ▶ Research items (tiered) ▶ Bundle (frozen, hashed)
 ▶ DRAFTER agent ▶ validator (deterministic) ▶ REVIEWER agent ▶ arbiter/gate ▶ persist ▶ render
```

### 4.1 Provider-agnostic agents
- **Interface:** `LlmProvider.complete({system, messages, schema, temperature, seed?}) → {text, json, usage}`. Adapters: Claude (API/Bedrock), OpenAI/ChatGPT, Gemini, Groq, local. Routine, prompts, schemas and validator are **provider-independent** — a "routine pack" (versioned prompts + JSON schemas + contract) that any provider can run.
- **Roles (separate calls, separate system prompts; may use different providers):**
  1. **Drafter** — receives only one scrip's frozen bundle; writes structured answers per sub-question.
  2. **Reviewer** — receives the bundle + draft; applies the rubric (§4.3); returns defects with locations; cannot add facts.
  3. **Arbiter** — deterministic code: validator + completeness gate + loop control (max 2 revise loops, then human escalation).
- **Development vs handover:** Claude drafts and tunes; once the routine and tests are final, the same pack runs unchanged under ChatGPT or another provider. A **parity test** runs the same bundle through two providers and compares structured output against the validator and golden facts.

### 4.2 Number provenance (the key control)
Every number in an answer must be emitted as a structured claim `{value, unit, period, scope, factId|calcId}`; prose is rendered from claims. The validator resolves each `factId/calcId` in the bundle and checks value (tolerance), unit, period, scope. Any numeric token not backed by a claim **fails**. This replaces the existing word-count validator.

### 4.3 Reviewer rubric
Number traceability; period/scope/unit labels; as-of date and staleness (latest available period used?); conflicts retained and disclosed; no inference stated as fact (customer/supplier concentration, pass-through, backlog conversion, reverse-DCF assumptions); premise checks done; **all sub-questions terminal**; no cross-scrip text outside Q3/Q17 peer sections; secondary sources labelled; arithmetic recomputed from claims; conclusions follow from evidence (no verdict from templates).

## 5. Data foundation (rebuild before any report)

### 5.1 Ingestion rules
1. **Duration classification** per XBRL context (from start/end): discrete quarter, half-year YTD, nine-month YTD, annual. Take `OneD` for quarters; **de-cumulate** YTD to discrete only when both endpoints are filed; mark derived quarters `DERIVED` with formula.
2. **Quality checks at write:** sum of 4 discrete quarters ≈ annual (tolerance); unit normalisation to **crore as REAL** with explicit conversion record; magnitude sanity (flag >10³× change); scope retained as a key; one row per `(isin, scope, metric, period_type, period_start, period_end, vintage)`; restatements create new vintages ordered by `available_at` (point-in-time).
3. **Metric vocabulary:** one canonical name per metric with a definition table (e.g., `revenue_from_operations`, `total_income`, `ebitda_derived`); provider labels map to these; **Total Rev. ≠ revenue_from_operations**.
4. **Provider tiers:** `STATUTORY` (XBRL/FERE, NSE/BSE) > `PROVIDER_VERIFIED` (Trendlyne with real period) > `PROVIDER_LATEST` (undated) > `SECONDARY_LEAD`. `SIMULATED` is never readable. Reads filter by tier and verification; undated `LATEST*` never used for time-series.
5. **Quarantine, don't delete:** flag all `TRENDLYNE_MCP_MAX` rows and any row produced by the simulator `quarantined=1`; remove the simulator from the production path (fail closed if no real response).
6. **Identity:** symbol/ISIN history in the registry; single `companyId` space; reject synthetic ISINs from fundamentals.

### 5.2 Backfill plan (non-destructive)
Re-derive discrete quarters and annuals from raw `verified_xbrl_fact` into the new clean table; run the reconciliation checks; produce a **before/after report** of every changed value for the six scrips (golden tests: YUKEN FY25 discrete quarters sum to 457.356; YUKEN Q2 FY25 revenue 115.66; VMART eight-quarter result = FAIL; TATATECH EBITDA 852.95 reproduced or discrepancy explained).

### 5.3 New schema (approved by owner on 2026-10-10 in chat; to be added to the sign-off log and created through **numbered migrations**, not runtime DDL)
| Table | Purpose |
|---|---|
| `canonical_period_facts` | Clean facts: isin, scope, metric, period_type, period_start/end, value REAL, unit, source, source_tier, available_at, vintage, supersedes_id, derivation, quality_flags, quarantined |
| `metric_definitions` | Canonical metric name, definition, unit, period basis, provider mappings |
| `trendlyne_parameter_catalog` | Full enumerated tokens: token, label, category, unit, period type, mapped_metric, tier |
| `trendlyne_call_log` | Every call: purpose, symbols, tokens, status, quota error, cost, cache key |
| `research_items` | Third-party/primary items: url, tier, publisher, dates, excerpt, status, traced_to |
| `answer_store` | Sub-question answers: run, scrip, sub_question_id, state, claims JSON, evidence refs, review status |

## 7. Deterministic calculation library (replaces "LLM computes")
Implemented in code, unit-tested, each returning value + inputs + formula + period/scope + status (`OK | INSUFFICIENT_DATA | NOT_APPLICABLE`):
returns (1/5/20 sessions, on adjusted close, window `close[-1]/close[-1-n]`), relative return vs index, volume/delivery abnormality · ADTV 20/60 (**value traded from raw close × raw volume, or adjust volume**), exit days = position value ÷ (participation × ADTV) with explicit participation (0 allowed) · SMA/EMA, ATR, swing pivots, volume-at-price, 52-week levels, bar-integrity incl. **staleness vs as-of** · revenue/EBITDA/PAT discrete quarters, YoY, sequential, CAGR 3/5y, margins (EBITDA derived and cross-checked) · CFO/PAT, accruals (needs total assets), FCF = CFO − capex (flag PPE-only capex), reinvestment rate · DSO/DIO/DPO/CCC on aligned periods, average balances when both ends exist · ROIC/ROCE/ROE with stated capital definition, incremental ROIC · net debt/EBITDA, interest coverage, 25-bp sensitivity (floating-debt split required; otherwise `INSUFFICIENT_DATA`, never total debt) with pre-tax first, after-tax only if tax rate evidenced · valuation multiples with own-history percentile · reverse DCF only with explicit, stored assumptions (label as illustrative).

**Readiness rule (replaces existence test):** a sub-question is `READY` only when every required input exists with: correct scope, period type and coverage (e.g., ≥8 discrete quarters; ≥5 years), unit validated, source tier ≥ required, freshness within allowed lag, and no unresolved conflict above tolerance.

## 8. Scores, verdicts and existing artifacts

If a scoring framework is wanted (QGLP), it must have documented inputs, a growth input derived from discrete quarters, a quality-of-earnings input (CFO/PAT, accruals, exceptional items), missing-data handling = `UNVERIFIABLE` (not low score), and be back-tested before use.
2. **Disable `DownstreamWaterfallEnricher`'s hash-derived statuses** in any production path; mark derived tables as synthetic.
3. **ScripIntelligenceDossierService** linear "factor scores", fixed targets (CMP × 1.22/1.14), stop (CMP × 0.93), "calibrated probability" and Kelly sizing have no data backing: label as illustrative or remove until calibrated.
4. **Mark existing reports** (YUKEN, AKIKO, nine-stock, any `institutional29` output) as **UNRELIABLE – REGENERATE** in the app until replaced (owner decision, §11).
5. Reports must state: "analysis of evidence; not personalised investment advice".

## 9. 29-question template and report layout
- **Sub-question table:** keep v1 §4 (authoritative). **Question numbering:** the contract (`contract.mjs`) is the single source of truth; three different numberings exist across files — retire the others.
- **Premise checks** (Q1 direction; Q2/Q4 order book; Q24 floating-rate debt) before answering; answer the underlying question when false.
- **No word cap;** length follows completeness. Every sub-question has a terminal state (`ANSWERED | PARTIAL | NOT_DISCLOSED | NOT_APPLICABLE`). Remove boilerplate tails and unsupported "answers all 29" statements.
- **Per-scrip standalone report layout:** (1) top summary: what the company is, headline evidence-based view, strengths/risks, data-completeness score, **the seven-filter table (§3.3)**; (2) 29 questions with sub-question answers; (3) evidence appendix: facts and calcs with ids, conflicts, gaps, research items, sources searched.
- **Independence:** one bundle and one drafting call per scrip; leakage check (other scrips' names/data only in Q3/Q17 peers).
