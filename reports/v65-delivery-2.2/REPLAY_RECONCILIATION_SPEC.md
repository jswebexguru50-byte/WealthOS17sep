# Replay Reconciliation Specification
**Phase 0 Discovery Artifact for Delivery 2.2**

This specification defines the required reconciliation barrier that must be integrated before metrics are allowed to run in Delivery 2.2.

## The Reconciliation Invariant

To ensure that the replay engine is empirical and not silently dropping inconvenient observations, the system must definitively account for every generated signal observation.

For any given Strategy ID over the entire scope, the following identity must hold exactly:

```text
Σ Candidate Observations
========================
  Σ Executed Trades
+ Σ DATA_INSUFFICIENT Trades
+ Σ Explicitly Rejected Observations
```

## Field Definitions

1. **Candidate Observations**: The total number of valid setups generated by the `PureTechnicalStrategiesEngine` (i.e., `qualified === true`).
2. **Executed Trades**: The number of candidate observations that successfully passed through `EntryResolutionEngine` and `ExitResolutionEngine` with valid prices, resulting in a finalized trade inserted into the Canonical Ledger.
3. **DATA_INSUFFICIENT Trades**: The number of candidate observations that could not be executed because required downstream data was missing (e.g., missing intraday data for S10, or no NEXT_OPEN bar available). This count must be explicitly tracked and logged.
4. **Explicitly Rejected Observations**: The number of candidate observations that were rejected by a specific active constraint engine (e.g., failed PIT validation in `PointInTimeDataEngine`, failed liquidity constraints, gap entry collisions, or portfolio capacity limits).

## Enforcement Mechanism
1. A new test file `tests/v65/ReplayReconciliation.test.ts` must be created to assert this invariant for every strategy evaluated.
2. The Economic Replay Engine must generate a `reports/v65-delivery-2.2/REPLAY_RECONCILIATION.json` artifact at the end of execution containing the counts for each category.
3. If the invariant fails (i.e., unexplained observations "disappear" between signal generation and ledger insertion), the entire pipeline must `throw new ReconciliationError()` and halt before metrics or statistics can consume the ledger.
