## New and remaining defects (blocking)
**N1 — Q3 derived from the wrong base (wrong value).** `deriveMissingQuarters` subtracts "any fact at the previous quarter end" — which can be the *discrete* Q2 instead of the *YTD_6M*. Probe A: Q1=100, Q2=100, YTD_6M=200, YTD_9M=330 → derived Q3 = **230** (should be 130). Rule: Q2 = YTD_6M − YTD_3M (or − Q1 discrete); Q3 = YTD_9M − **YTD_6M**; Q4 = YTD_12M − **YTD_9M**; always subtract the previous *cumulative* YTD of the same chain.

**N2 — Cross-metric contamination (fabricated numbers).** The lookup `facts.find(f => f.periodEnd === prevEnd …)` ignores `metric`, `scope` and `isin`. Probe D: SALES Q1 = 50,000 Cr and PAT YTD_6M = 24.73 → derived **PAT Q2 = −4,975.27** (subtracted a different metric). Probe C: PAT Q2 is *not* derived because SALES already has a Q2. Probe F/G: Q4 derivation is suppressed whenever *any* metric (or any other fiscal year) has a Q4 discrete. All "exists" checks must be keyed by `(isin, scope, metric, fiscal year, period type)`.

**N3 — Cross-scope contamination.** Probe E: consolidated Q2 derived from **standalone** Q1 (−8.87). Scope must be part of every derivation key.

**N4 — Derived period dates wrong.** Probe H: derived Q2 `periodStart` = `2025-06-30` (should be the quarter start `2025-07-01`); derived Q4 reuses the annual start. Compute quarter start/end from the quarter index.

**N5 — Type-check failure.** `xbrlPeriods.ts(11,579): error TS2551: Property 'value' does not exist on type 'Fact'` (`prior.value`). `tsx` does not type-check, so the tests hide it; `npm run lint` will fail. Run `tsc --noEmit` on the files and fix. This bug also makes **every duplicate row flagged `RESTATED`** (probe I: an *identical* row from another filing gets vintage 2 + `RESTATED`) because `undefined !== value` is always true.

**N6 — Reconciliation gating.** `continue` after `RECON_UNVERIFIED` skips the YTD/discrete checks whenever the annual total or exactly four quarters are absent (probe N: Q1=100, Q2=100, YTD_6M=500 is **not** flagged `PERIOD_RECON_FAIL`). Also `RECON_UNVERIFIED` is stamped on balance-sheet (`POINT_IN_TIME`) facts and on Q1 duplicates (probes M, O). Checks must be independent: (a) Σ four quarters ≈ annual, (b) YTD_6M ≈ Q1+Q2, (c) YTD_9M ≈ Q1+Q2+Q3, (d) discrete ≤ YTD; `RECON_UNVERIFIED` only for flow facts whose group lacks the inputs for *all* applicable checks.

**N7 — Vocabulary does not match the real raw table.** Real `verified_xbrl_fact.metric` names include `sales`, `pat`, `pbt`, `finance_costs` (plural), `materials_cost`, `depreciation`, `cfo`, `equity_capital`, `total_expenses`, and hundreds of `xbrl_*` names (e.g. `xbrl_other_income`, `xbrl_tax_expense`, `xbrl_profit_before_exceptional_items_and_tax`, `xbrl_exceptional_items_before_tax`, `xbrl_profit_or_loss_attributable_to_owners_of_parent`, `xbrl_income`). Probe R: `finance_costs`, `materials_cost` throw `METRIC_UNMAPPED`. Provide an **explicit raw→canonical mapping table** for the metrics the program uses (verify each meaning against the data — e.g. `xbrl_income` vs `total_income` — do not guess), and treat every other raw metric as deliberately out of scope.

**N8 — One unmapped row aborts the batch.** `classifyPeriod` throws; `normalizeXbrlFacts` has no rejection path, so a real backfill (hundreds of unmapped `xbrl_*` metrics) would crash on the first one. Return `{ facts, rejected: [{rawMetric, reason, count}] }` and never throw for data-driven reasons; keep throws only for programmer errors.

**N9 — Per-share units.** Real units include `INRPerShare` (EPS, face value). `convertUnit` rejects it. Either add a distinct `INR_PER_SHARE` unit or exclude per-share metrics via the mapping (document which).

**N10 — Vintage history not retained.** Normalisation keeps only the latest vintage per key (probe J: 2 filings → 1 output). The store (S2) needs the history; return all vintages (latest flagged) or expose both. Identical re-filings must not create a new vintage (N5).

**N11 — Source tier.** Tier must come from the input (`RawXbrlFact.sourceTier`/source mapping) and an unknown tier must be rejected — never default to `STATUTORY` (S1-9 still open; probes P, Q).

**N12 — Magnitude check.** Compare with the **adjacent period of the same key** (same isin, scope, metric, period type; previous period end) and mark `UNIT_SUSPECT`; keep the same-period restatement comparison as a separate flag. Required test: YUKEN `equity_capital` FY25 1.3e13 INR vs FY26 1.36e8 INR; and a flow example (PAT 5e9 then 5e6 next quarter).

**N13 — Readability.** `xbrlPeriods.ts` now contains lines of 400+ characters (derivation, reconcile). This is not reviewable or maintainable. Format with the project's formatter/Prettier, one statement per line, small named helpers (`deriveQuarterFromYtd`, `reconcileAnnual`, `reconcileYtd`, …).
