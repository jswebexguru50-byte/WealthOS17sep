# WealthOS 29-Question Research Program V2 — Implementation Plan (v1.1, corrected after review, 2026-10-10)

## Objective
Build the 29-question **fundamental analysis** research pipeline as a separate, provider-neutral, evidence-bounded subsystem. It preserves raw facts, classifies periods/units/scope correctly, exposes data gaps, validates every numerical claim, and produces one standalone report per scrip with no rankings, no overall pass/fail, no buy/sell labels and no invented values.

**Authoritative documents** (all on `ai-review` after the docs merge): `WEALTHOS_29Q_V2_BUILD_SPEC_2026-10-10.md` **including its Amendment 1 at the top (Amendment 1 wins on any conflict)**, `WEALTHOS_29Q_AUDIT_AND_SPEC_V2_2026-10-10.md`, `WEALTHOS_29Q_SIX_SCRIP_PROGRAM_SPEC_2026-10-10.md` §4, `AGENT_CONSTITUTION.md`, `IMPLEMENTATION_PLAN.md`, `WEALTHOS_MASTER_REVIEW_AND_SPEC_2026-10-08.md` §9–10.

## Coordination and boundaries
- Base: latest `origin/ai-review` (it now contains the specs). One branch and one PR per slice, targeting `ai-review`; never commit or push directly to `ai-review` or `master`.
- Work in an isolated area that is **not** the Downloads checkout used by the other remediation stream. Enable `git config core.longpaths true` and/or use a sparse/partial clone (worktrees failed here with "Filename too long").
- **Allowed paths only:** `src/server/research_v2/**`, `src/server/routes/researchV2.ts`, `src/server/db/migrations/research_v2_schema.sql`, `src/server/db/migrations/research_v2_migration.ts`, `tests/research_v2/**`, `scripts/research_v2/**` (+ report artifacts under `docs/research_v2/artifacts/`), `src/components/research/**` (S9), and the sign-off line in `IMPLEMENTATION_PLAN.md`.
- **Read-only for the bot:** existing routes, components, migrations 001–014, `migrations/index.ts`, `server.ts`, `database.ts`, `fifoEngine.ts`, all real databases. The bot never moves the ACTIVE phase marker; the owner/integrator does (new phase "WEALTHOS_29Q_V2 — fundamental analysis only" approved 2026-10-10).
- Real data is read-only (`mode=ro`, `PRAGMA query_only=ON`); writes use fixtures or an explicitly supplied database copy. No package installation without owner approval.
- **Scope: fundamental analysis only.** Technical/price-action/liquidity work, OHLCV and DuckDB are deferred. Contract questions Q1, Q28, Q29 stay in the numbering and resolve to `NOT_APPLICABLE` ("Out of scope: fundamental analysis only (deferred)").
- **No LLM API key is expected.** Host-agent mode: the executing agent drafts with its own LLM and spawns a separate reviewer sub-agent; API adapters are optional and disabled by default.
- Trendlyne keys already exist in project configuration; read them from there and never print or copy them.
